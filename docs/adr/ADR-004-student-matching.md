# ADR-004: Сопоставление студента

- Статус: принято
- Решение: точное совпадение после NFKC, нормализации пробелов/регистра и `ё→е` по ФИО, uppercase группы; институт не вводится. Допустимо только ровно одно active совпадение.
- Альтернативы: fuzzy matching и перестановка частей ФИО отклонены из-за риска выдать чужой кабинет. `source_id` не вводится, потому что студент может его не знать.
- Последствие: дубли требуют ручного разрешения; общий текст ошибки не позволяет enumeration. Эквивалентность `ё/е` требует бизнес-подтверждения.
