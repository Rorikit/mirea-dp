# Функциональные требования

| ID | Требование | Приёмка |
|---|---|---|
| FR-01 | Администратор загружает `.xlsx` по шаблону | Файл только проверяется и помещается в staging — промежуточную область. |
| FR-02 | Система валидирует, нормализует, сравнивает и показывает preview | Видны CREATE/UPDATE/UNCHANGED/DEACTIVATE/ERROR, исходные и будущие значения. |
| FR-03 | Администратор подтверждает импорт | Без ERROR, после согласия с WARNING; изменения применяются одной транзакцией. |
| FR-04 | Хранится история импортов и отчёт ошибок | Статус, счётчики, автор, hash, времена и `.xlsx`-отчёт доступны администратору. |
| FR-05 | Студент ищет себя по ФИО и группе | Только точное совпадение после нормализации; ответы не раскрывают чужие данные. |
| FR-06 | Создаётся одна регистрация на студента и событие | Повтор запроса возвращает существующую регистрацию. |
| FR-07 | Студент видит свой профиль, статус и QR | `OUTSIDE`/`INSIDE`, только один активный токен. |
| FR-08 | Оператор сканирует/вводит QR | Один успешный запрос создаёт один переход и показывает минимум данных. |
| FR-09 | Сохраняется история всех попыток и успешных событий | `ScanAttempt` хранит успехи/ошибки; `AttendanceEvent` — только совершившиеся переходы. |
| FR-10 | Студент видит опубликованные карту и расписание | Статусы расписания вычисляются по серверному времени Москвы. |
| FR-11 | Администратор управляет пользователями и контентом | RBAC, аудит каждой мутации. |
| FR-12 | Дашборд и экспорт поддерживают фильтры | Определения метрик едины; Excel защищён от formula injection. |
| FR-13 | Архивирование события заменяет destructive reset | История сохраняется; новое мероприятие начинается с пустого состояния. |

## Вне MVP

Офлайн-сканирование, WebSocket, интерактивные зоны карты, SSO, автоматическое fuzzy matching — нечёткое сопоставление, физическое удаление истории, микросервисы и мобильные native-приложения.
